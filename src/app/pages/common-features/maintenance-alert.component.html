Common Features

System Maintenance Alert

Schedule, manage, and communicate planned maintenance windows to all users. Live banner, auto-redirect, email notifications via Hangfire, and developer bypass.

Completed

Overview

  • Live banner appears at the top of every page when maintenance is approaching or active
  • Auto-redirect to /maintenance page when maintenance starts
  • Email notifications — manual send or auto-scheduled via Hangfire background job
  • Bypass mechanism — /bypass sets a cookie so developers can test during maintenance
  • Two-layer redirect — banner setTimeout + route guard for backgrounded tabs

Status Values

ValueNameBannerRedirectsAuto EmailDescription
"1"DraftNoNoNoBeing prepared
"2"ActiveYesYesNoLive alert; users redirected
"3"CompletedNoNoNoStops banner + redirect immediately
"4"ScheduledYesYesYesHangfire job fires at start - alert minutes
"5"CancelledNoNoNoAny Hangfire job is cancelled
To stop the maintenance alert immediately, set status to "3" (Completed).

Hangfire Auto-Email Job

Class: MaintenanceAlertEmailJob in Infrastructure/BackgroundServices/

Method: SendEmailAuto(string maintenanceId)

Job Lifecycle

TriggerAction
Save with Status="4"Old job deleted → new job scheduled → ScheduleJobId saved
Save with other statusOld job deleted → ScheduleJobId cleared
Delete recordJob deleted → record soft-deleted
Job firesSends email → Status="3", ScheduleJobId=null, EmailSentOn set

Guard Checks

  • Record not found or Active=false → skip
  • EmailSentOn already set → skip (idempotent)
  • Status != "4" (admin changed it) → skip

Email Notification

Recipient Logic

  1. Collect all ContactEmail from SysLicense where Active=true
  2. Add ReceiverMail from alert record
  3. Filter through IsValidEmail(), deduplicate
  4. Send one email per TO recipient via AWS SES
  5. Send CC separately if CcreceiverMail is set

Live Banner & Redirect

Component: MaintenanceAlertBannerComponent — placed in vertical.component.html for all logged-in users.

  • Polls GetActiveAlert every 5 minutes
  • Upcoming (before start): clock icon + scheduled time range
  • In Progress (after start): wrench icon + "Ongoing until..." message
  • Dismiss hides UI only — redirect timer continues running

Two-Layer Redirect Coverage

ScenarioCovered By
User active on any page when maintenance startsBanner setTimeout
User's tab was backgrounded (timer throttled)MaintenanceGuard on next navigation
User opens new tab after maintenance startedBanner checkAlert() → immediate redirect

Developer Bypass

Route: /bypass — sets smarthr_bypass=true cookie (4 hours), then redirects to /.

  • Banner and guard both check this cookie — skip redirect if present
  • Cookie expires after 4 hours automatically
  • For IIS-level maintenance: use /_bypass.html (static file in IIS root)
// Usage during deployment testing:
Dev team visits: https://hr_qa.smarticwork.com/bypass
  → cookie set → redirected to / → system loads normally
  → other users without cookie → still redirected to /maintenance
